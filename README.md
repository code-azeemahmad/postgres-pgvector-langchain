## Overview

Setting up a vector database locally does not have to be complicated. This project provides a ready-to-run setup using **Docker Compose** to launch:
1. **PostgreSQL 16** with the **`pgvector`** extension pre-installed.
2. **pgAdmin 4** for graphical management and inspecting vector embeddings.

Using **LangChain**'s official `langchain-postgres` library and `PGEngine`, the application demonstrates how to create vector tables, index embeddings generated by **Ollama**, and perform similarity searches with metadata filtering.

## Key Features

- **One-Command Docker Setup**: Starts PostgreSQL with `pgvector` and `pgAdmin 4` in isolated containers with persistent volumes.
- **Automated Extension Setup**: Automatically runs `CREATE EXTENSION IF NOT EXISTS vector;` on PostgreSQL startup via `init.sql`.
- **Modern LangChain Integration**: Uses `langchain-postgres` with `PGEngine` and `psycopg3` for native PostgreSQL vector operations.
- **Dynamic Vector Dimensioning**: Dynamically computes embedding dimensions from the active embedding model, avoiding manual table schema hardcoding.
- **Metadata Filtering**: Demonstrates storing and querying custom metadata columns (such as `department` and `tenant_id`) alongside vector embeddings.
- **pgAdmin 4 Web Dashboard**: Pre-configured container to visually inspect tables, schema definitions, and vector columns.
- **100% Local AI Stack**: Integrates with local models via Ollama for zero data leakage and cost-free local development.

## Step-by-Step Setup

### 1. Clone Repository

```bash
git clone https://github.com/your-username/postgres-pgvector-langchain.git
cd postgres-pgvector-langchain
```

### 2. Configure Environment Variables

Copy `.env.sample` to `.env`:

```bash
cp .env.sample .env
```

Verify your `.env` contents:

```env
POSTGRES_HOST=
POSTGRES_PORT=
POSTGRES_DB=
POSTGRES_USER=
POSTGRES_PASSWORD=

OLLAMA_BASE_URL=
OLLAMA_EMBEDDING_MODEL=
OLLAMA_LLM_MODEL=
```

---

### 3. Start PostgreSQL and pgAdmin with Docker

Run Docker Compose to spin up the PostgreSQL (with `pgvector`) and pgAdmin containers:

```bash
docker compose up -d
```

Check the status of your containers:

```bash
docker compose ps
```

You should see both `pgvector-postgres` (healthy) and `pgadmin` running.

---

### 4. Set Up Python Environment & Dependencies

Create a virtual environment and install the required dependencies:

**Windows (PowerShell):**
```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

**macOS / Linux:**
```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

The key dependencies installed are:
- `langchain-postgres`: Official LangChain PostgreSQL vector store & engine
- `langchain-ollama`: Ollama embeddings & chat LLM integration
- `psycopg[binary]`: PostgreSQL driver for Python

---

### 5. Pull Ollama Models (Local Embeddings & LLM)

Ensure Ollama is running (`ollama serve`), then pull the embedding model and chat model:

```bash
ollama pull nomic-embed-text
ollama pull qwen2.5-coder:14b
```
*(You can use any LLM model available in Ollama, such as `llama3.2`, `mistral`, or `phi3` by updating `OLLAMA_LLM_MODEL` in `.env`)*.

---

### 6. Initialize the Vector Store & Ingest Data

Run [`app/setup_db.py`](file:///f:/postgres-pgvector-langchain/app/setup_db.py) to:
1. Connect to PostgreSQL using `PGEngine`.
2. Create the vector table (`knowledge_documents`) with custom metadata columns.
3. Generate embeddings via Ollama and store the sample documents in `pgvector`.

```bash
python -m app.setup_db
```

**Sample Output:**
```

Inserted 5 documents.
Database setup complete.
```

Start the interactive CLI knowledge assistant:

## Docker Configuration Explained

### `docker-compose.yml`

The Compose file orchestrates two services:

1. **`postgres` service (`pgvector/pgvector:pg16`)**:
   - Uses the official `pgvector` Docker image with PostgreSQL 16.
   - Mounts [`init.sql`](file:///f:/postgres-pgvector-langchain/init.sql) into `/docker-entrypoint-initdb.d/` to run initialization scripts on first boot.
   - Sets a healthcheck using `pg_isready`.
   - Persists data using the `postgres_data` volume.

2. **`pgadmin` service (`dpage/pgadmin4:latest`)**:
   - Provides a web dashboard on port `5050`.
   - Waits for the `postgres` service to be healthy before starting.
   - Persists settings using the `pgadmin_data` volume.

```yaml
services:
  postgres:
    image: pgvector/pgvector:pg16
    container_name: pgvector-postgres
    environment:
      POSTGRES_DB: ai_knowledge
      POSTGRES_USER: postgres
      POSTGRES_PASSWORD: postgres
    ports:
      - "5432:5432"
    volumes:
      - postgres_data:/var/lib/postgresql/data
      - ./init.sql:/docker-entrypoint-initdb.d/init.sql
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U postgres -d ai_knowledge"]
      interval: 5s
      timeout: 5s
      retries: 10

  pgadmin:
    image: dpage/pgadmin4:latest
    container_name: pgadmin
    environment:
      PGADMIN_DEFAULT_EMAIL: admin@example.com
      PGADMIN_DEFAULT_PASSWORD: admin123
    ports:
      - "5050:80"
    volumes:
      - pgadmin_data:/var/lib/pgadmin
    depends_on:
      postgres:
        condition: service_healthy

volumes:
  postgres_data:
  pgadmin_data:
```

### `init.sql` (Vector Extension Initializer)

When PostgreSQL initializes the database for the first time, it executes files in `/docker-entrypoint-initdb.d/`. [`init.sql`](file:///f:/postgres-pgvector-langchain/init.sql) enables the `vector` extension:

```sql
CREATE EXTENSION IF NOT EXISTS vector;
```

## Connecting LangChain to PostgreSQL (`langchain-postgres`)

### Engine Setup (`PGEngine`)

In [`app/db.py`](file:///f:/postgres-pgvector-langchain/app/db.py), we initialize the `PGEngine` using the standard `postgresql+psycopg://` URI scheme:

```python
from langchain_postgres import PGEngine

CONNECTION_STRING = (
    f"postgresql+psycopg://"
    f"{POSTGRES_USER}:{POSTGRES_PASSWORD}"
    f"@{POSTGRES_HOST}:{POSTGRES_PORT}"
    f"/{POSTGRES_DB}"
)

pg_engine = PGEngine.from_connection_string(url=CONNECTION_STRING)
```

### Dynamic Vector Dimension Handling

In [`app/ingest.py`](file:///f:/postgres-pgvector-langchain/app/ingest.py), instead of hardcoding the dimension size (e.g. 768 or 1536), we infer it dynamically from the embedding model:

```python
embeddings = OllamaEmbeddings(model=EMBEDDING_MODEL, base_url=OLLAMA_BASE_URL)

# Determine embedding dimension dynamically
VECTOR_SIZE = len(embeddings.embed_query("dimension check"))

def initialize_vector_store():
    pg_engine.init_vectorstore_table(
        table_name="knowledge_documents",
        vector_size=VECTOR_SIZE,
        metadata_columns=[
            Column("department", "VARCHAR"),
            Column("tenant_id", "VARCHAR"),
        ],
    )
```

### Metadata Filtering & Similarity Search

In [`app/search.py`](file:///f:/postgres-pgvector-langchain/app/search.py), similarity search can filter on indexed metadata columns:

```python
def semantic_search(
    query: str,
    k: int = 3,
    tenant_id: str | None = None,
    department: str | None = None,
):
    store = get_vector_store()
    filter_dict = {}

    if tenant_id is not None:
        filter_dict["tenant_id"] = tenant_id
    if department is not None:
        filter_dict["department"] = department

    return store.similarity_search(
        query,
        k=k,
        filter=filter_dict or None,
    )
```

## Inspecting Vectors in pgAdmin

You can view your PostgreSQL tables and vector records directly in pgAdmin:

1. Navigate to **[http://localhost:5050](http://localhost:5050)**.
2. Log in with:
   - **Email**: `admin@example.com`
   - **Password**: `admin123`
3. Add your server:
   - Right-click **Servers** > **Register** > **Server...**
   - **General** tab -> Name: `pgvector-postgres`
   - **Connection** tab ->
     - **Host name/address**: `postgres` (internal docker name) or `host.docker.internal`
     - **Port**: `5432`
     - **Maintenance database**: `ai_knowledge`
     - **Username**: `postgres`
     - **Password**: `postgres`
4. Expand **Databases** > **`ai_knowledge`** > **Schemas** > **public** > **Tables** > **`knowledge_documents`**.
5. View table rows to see stored text, metadata columns, and vector embeddings.

## Troubleshooting

| Issue | Cause | Solution |
| :--- | :--- | :--- |
| **`Connection refused: localhost:5432`** | Docker container is stopped or still starting. | Run `docker compose up -d` and verify with `docker compose ps`. |
| **`extension "vector" is not available`** | Using standard postgres image instead of pgvector. | Verify `image: pgvector/pgvector:pg16` is used in `docker-compose.yml`. |
| **`Ollama connection error`** | Ollama service is not running or model not pulled. | Run `ollama serve` and pull models (`ollama pull nomic-embed-text`). |
| **`Vector dimension mismatch error`** | Changed embedding model without re-initializing table. | Run `python -m app.setup_db` to re-create the table with matching dimensions. |
| **`Event loop is closed` (Windows)** | Windows asyncio event loop incompatibility with psycopg3. | Solved automatically via `WindowsSelectorEventLoopPolicy` in `app/db.py` & `app/main.py`. |

## Stopping the Containers

To stop the containers without removing data:
```bash
docker compose stop
```

To stop and remove containers (preserving database volume):
```bash
docker compose down
```

To wipe the database volume completely:
```bash
docker compose down -v
```
